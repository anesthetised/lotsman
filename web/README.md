# Lotsman web panel (frontend)

The browser UI served by `lotsman web`: the operator console under `/admin` and
the user page behind a secret link, `/u/<token>`. It talks Connect to the panel
(`/api`), which forwards the daemon control API from [`api/`](../api).

Stack: Solid 2, @solidjs/router 2, Kobalte 2 (behind our own components in
`src/ui`), Tailwind 4, uPlot, Connect-web with protobuf-es v2. pnpm, Vite,
Vitest and Playwright.

## Commands

Needs Node 22.12+ (CI runs 24) with corepack enabled (`corepack enable`), which
runs the pnpm pinned in `package.json`. From the repository root:

| Recipe             | What it does                                                         |
| ------------------ | -------------------------------------------------------------------- |
| `just web-install` | Locked install (`--frozen-lockfile`) and Playwright's Chromium.      |
| `just web-dev`     | Dev server with hot reload, against the in-memory fake daemon.      |
| `just web-build`   | Production build into `internal/web/dist`.                           |
| `just web-test`    | Typecheck, Vitest, then the Playwright smoke test.                   |
| `just web-gen`     | Regenerate `src/gen` from `api/` after a proto change; commit it.    |

Inside `web/`, `pnpm dev | build | typecheck | test | e2e | gen` do the same.

## Layout

- `src/gen`: generated by `buf generate` (`buf.gen.yaml`). Committed; CI fails if it is stale.
- `src/api`: the clients (`client.ts`), the fake daemon (`fake.ts`, `simulation.ts`),
  helpers that turn Watch streams into reactive values (`live.ts`), and operator
  sign-in: the `/auth` client (`auth.ts`), WebAuthn JSON conversions (`webauthn.ts`)
  and the fake panel auth (`fakeAuth.ts`).
- `src/ui`: our components. Only this folder imports Kobalte, so a breaking
  Kobalte alpha touches one folder.
- `src/i18n`: the typed dictionaries and Intl formatters.
- `src/pages`: `admin/` (dense, desktop and tablet), `auth/` (`/login`, `/enroll`)
  and `user/` (mobile first).
  Each is its own lazy chunk: the user page never downloads uPlot or Kobalte's menus.
- `e2e`: Playwright smoke tests.

## Fake daemon and sign-in

`VITE_FAKE_API=1` (set by `.env.development`, `.env.test` and `.env.e2e`) makes
`src/api/client.ts` use `createRouterTransport` over a deterministic traffic
simulation instead of `createConnectTransport({ baseUrl: "/api" })`. A plain
`vite build` has the variable unset, so the fake is dropped from the bundle.
Methods the fake does not implement answer `Unimplemented`, like the daemon
before their issue lands. The fake follows the contract where the pages rely
on it: history rounds `step` up to 1 min (last 7 days) or 1 h and to at most
2000 samples; the user's `Watch` leaves upstream `traffic`, `routed` and
`active` unset; `UserSelfService.UpstreamHistory` carries no bytes, and both
user history RPCs answer `NotFound` outside the user's upstreams and peers.

The same variable swaps the panel's `/auth` endpoints for `src/api/fakeAuth.ts`,
which keeps its state in `sessionStorage`. It starts signed in as the operator
`dev`, so the console opens at once; **Sign out** and then `/enroll#dev` (the
token works once per tab) or **Sign in** run real passkey prompts against it.
It checks the client data (type, challenge, origin), not signatures; the Go
tests cover those. While signed out, the fake daemon answers operator calls
with `Unauthenticated`, as the panel does. The Playwright test `e2e/auth.spec.ts`
uses Chromium's virtual authenticator (CDP `WebAuthn.addVirtualAuthenticator`).

`pnpm e2e` builds with `--mode e2e` (a production build with the fake inside,
in `dist-e2e/`) and runs Playwright against `vite preview`, which sends the CSP
the panel should send. Any console error, CSP violation or request to another
origin fails a test.

## Build output

`vite build` writes to `internal/web/dist`, which the Go side embeds with
`//go:embed all:dist`. The output is git-ignored; git tracks only
`internal/web/dist/.gitkeep`, so `go build` works without Node and `lotsman web`
then serves its own "UI not built" page. Vite empties the directory before each
build and a small plugin in `vite.config.ts` puts `.gitkeep` back; CI checks that
a build leaves `internal/web/dist` clean in git.

## Translations

`src/i18n/en.ts` defines the keys; `ru.ts` must have exactly the same shape (the
`Dict` type checks it). The language is the first supported one in the browser's
preferences, else English. Units come from `Intl`, not the dictionaries.

## Accessibility and security rules

- Keyboard first: every action is reachable and visible on focus; Kobalte
  handles focus traps, Escape and focus return in dialogs and menus.
- Colour never carries meaning alone (state badges have text); text tokens in
  `src/styles.css` meet WCAG AA in both themes. The theme follows `prefers-color-scheme`.
- Charts are canvas: give them a caption with the current values.
- No external assets (system fonts, inline SVG icons) and no inline scripts or
  styles in the build, so the page runs under `script-src 'self'; style-src 'self'`.
- The user page carries a secret in its URL: `<meta name="referrer" content="no-referrer">`
  is in `index.html`, and the panel also sends `Referrer-Policy: no-referrer`. The page's calls
  carry the token as `Authorization: Bearer <token>` (`selfApi` in `src/api/client.ts`); the panel
  resolves it and never forwards it. The fake ignores it.

## Pins and patches

Every version is exact, and `minimumReleaseAge` in `pnpm-workspace.yaml` refuses
any package (transitive ones too) published less than two weeks ago. As of
2026-11-19:

- Solid is `2.0.1` (with `@solidjs/web` and `@solidjs/signals`), the router
  `2.0.0` and the Vite plugin `@solidjs/vite-plugin@3.0.1`, which compiles with
  `@solidjs/compiler@2.0.1` (native, with a WASM fallback). They were published
  on 2026-11-17/18, so `minimumReleaseAgeExclude` lists exactly these versions,
  plus `seroval@1.8.0` and `seroval-plugins@1.8.0` (2026-11-09), which
  solid-js 2.0.1 requires. Exact versions only: a newer release of any of them
  still waits. Remove the seroval entries after 2026-11-23 and the rest after
  2026-12-02.
- `@solidjs/testing-library` stays `1.0.0-rc.2`, the newest; it accepts any Solid 2.
- `vite-plugin-solid@3.0.0-next.*` is only a shim that re-exports
  `@solidjs/vite-plugin`.
- pnpm is 11 (the JavaScript line): pnpm 12 ships a native binary that corepack
  0.33 cannot run.
- Kobalte `2.0.0-alpha.4` declares Solid `2.0.0-rc.16` as its exact peer;
  `peerDependencyRules` accepts our 2.0.1.
- `patches/@kobalte__core@2.0.0-alpha.4.patch`: in Solid 2 a signal write is
  visible only after the flush, so Kobalte's `DismissableLayer` read its ref as
  `undefined` in `onSettled` and never registered the layer, so Escape and
  outside clicks did nothing. Whether it shows depends on the markup (content
  placed directly in the portal breaks; our Dialog's wrapper div happens to hide
  it), so any dialog, menu, popover or select could hit it. The patch registers
  the layer from an effect on the ref. `src/ui/kobalte-patch.test.tsx` fails
  without it (still so on Solid 2.0.1). Drop the patch once a Kobalte release
  fixes this.

Solid 2 differs from 1.x in ways that are easy to get wrong (props are values,
effects take two functions, writes are not visible until the flush, flow
callbacks are not tracking scopes): read `node_modules/solid-js/CHEATSHEET.md`.
